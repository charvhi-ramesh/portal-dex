## Decisions taken in this plan (Claude's discretion, all reversible)

- **Order:** favourites insertion order (the store already keeps it), so a newly starred card appears last.
- **Removal mechanism:** the card's own star, which is the only control that changes favourites. A capture-phase click listener on the grid records which card is being removed (index, name, and whether focus was inside that card) before the store updates and before the card turns `inert`, which blurs it; all side effects (announcement, focus) run when Motion reports the exit finished, never in render and never through setState in an effect.
- **Request per change:** the query key is the sorted ID list with `keepPreviousData`, so a removal shows the remaining cards at once and refreshes the smaller list in the background (still one multi-ID request, never one per card).
- **Hand-off target:** the next card's flip button (its accessible name is the card label), via the shared `focusCard` helper; plan 03-04 moves Browse and the portal to the same helper.

## Flagged Assumptions

- **Missing IDs and the header count:** a stored ID the API no longer returns is skipped on /collection but still counted by the header ("N collected"); it stays stored because only the user's star press may change favourites.
- **Other-tab removals are not announced and never move focus:** only removals made on this page are recorded, so only they are announced and only they can move focus; a card removed from another tab simply leaves. Focus moves only when the `hadFocus` flag, read in the capture-phase click handler before the card turned inert, is set; focus on the body alone never counts as "lost". Consequence: if a card held focus in this tab and is then removed from another tab, its focus falls to the body and stays there (the next Tab continues from the browser's sequential focus starting point). Safari does not focus a button on mouse click, so a mouse removal in Safari records `hadFocus: false` and leaves focus where it was.
- **Background refresh after a removal:** the smaller ID list is refetched once in the background (cached for an hour), while the remaining cards stay on screen.
