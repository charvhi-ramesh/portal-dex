## PERF-02 pass rule (fails when) and remediation

Audited pages: /, /browse, /collection (once empty, once with three favourites in the same window), /character/1 and /no-such-page, on the deployed production URL, desktop Lighthouse in an incognito window with no extensions, Categories "Performance" and "Accessibility".

**Pass rule.** PERF-02 is recorded as met only when every audited page scores 90 or more for Performance AND 90 or more for Accessibility. Per page:
1. Run once. 90 or more on both categories passes that page.
2. If either category is under 90 but 87 or more, run that page twice more (three runs in total, never more; no best-of-N). A first run under 87 fails the page at once, with no re-runs. A median of the three runs may be used only to smooth run-to-run noise when the runs straddle 90 by a few points, meaning at least one run is 90 or more and every run is 87 or more; the page then passes only if that median is 90 or more.

**PERF-02 fails when** any audited page, in either category: has a first run under 90 that was not re-run; has all three runs under 90; has any run under 87; or has a median under 90. A median is never used to turn a sub-90 outcome into a pass, and a page that was not audited leaves PERF-02 pending, not met.

**Remediation path (inside this plan, when PERF-02 fails):**
1. Record every run's score verbatim, per page and category, in the SUMMARY and the UAT.
2. For each failing page, list the top three Lighthouse Performance opportunities or diagnostics by estimated savings (titles verbatim), and for an Accessibility shortfall every failed audit (titles verbatim).
3. Mark PERF-02 as "not met" in the SUMMARY and leave its REQUIREMENTS.md checkbox unchecked. DEP-01 is judged separately and can still be complete.
4. Surface it to the user as a decision (for example a gap-closure plan through `/gsd-plan-phase 3 --gaps`, folding it into Phase 4 "Light polish", or accepting the score), and change no code to chase the score within this plan.
