## Flagged Assumptions

- **[edge HOME-01 / unclassified, unresolved]** Assumed edges, not probe-verified: the portal is about 70% of the viewport width on mobile (`min(70vw, 22rem)`), the page has exactly one `h1`, the headline and explanation are plain copy without show references, and the page prerenders with the portal idle (no request until the user acts).
- **[edge HOME-05 / unclassified, unresolved]** Assumed edges, not probe-verified: reduced motion is read through `useMediaQuery("(prefers-reduced-motion: reduce)", true)`, so the server render and first paint are static and the idle rotation starts only after hydration when motion is allowed; under reduced motion the minimum spin time is 0 and the card fades in over 200 ms; switching the preference mid-spin stops the rotation at once.
- **One portal control (discretion):** SPEC 5.1 says "Clicking the portal (or the 'Open portal' button)". The disc and a visible "Open portal" pill are one `button`, so pointer users can click either and keyboard users meet one tab stop, not two identically named ones.
- **Last-known count key (discretion):** SPEC A8 asks for a cached or last-known count; the last-known value is stored as a positive integer string under `portal-dex:character-count`, written only after a successful count request and treated as a hint (dropping it is harmless). Rated reversible.
- **Motion package (SUS, too-new):** at planning time (2026-11-12) `package-legitimacy check --ecosystem npm motion` returned verdict SUS for one reason, `too-new`: latest 14.12.0 published 2026-11-10, about 34M weekly downloads, repository github.com/motiondivision/motion, no postinstall; dependencies `tslib` and `framer-motion` 14.12.0 (which pulls `motion-dom` 14.12.0 and `motion-utils` 14.7.0); peers react, react-dom and remix are all optional. Task 2 re-checks and the user chooses the exact version.
