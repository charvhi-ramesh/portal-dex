## Flagged Assumptions

- **[edge COL-02 / unclassified, unresolved]** Assumed edges, not probe-verified: a `window.localStorage` getter that throws (SecurityError), a `getItem` that throws, and a `setItem` that throws (QuotaExceededError) all switch the store to memory-only for the session without losing the current list; a corrupt value is not rewritten until the user's next toggle, which then stores the clean list; JSON with prototype-like keys is harmless because only array number entries are read.
- **[edge COL-03 / unclassified, unresolved]** Assumed edges, not probe-verified: the counter is not a live region (the star's pressed state is what assistive technology announces); under 640 px it always reads "N collected" so the header fits 320 px (UI-SPEC width budget), from 640 px it adds " / {total}" once the count query succeeds; a failed count query keeps the "N collected" form; thousands use `formatCount`.
- **Constant star label (discretion):** SPEC section 8 asks for `aria-pressed` and labels like "Add Rick Sanchez to collection". The name stays constant and `aria-pressed` carries the state, because swapping the label as well as the pressed state makes screen readers announce a contradiction ("Remove ..., pressed").
- **Total count request:** the header triggers one cached count request per session (`totalCountOptions`, staleTime 1 h), which also gives the portal a cached count; it is one list request, not per item.
- **Canon referral (not minted):** prototype pollution through stored JSON is canon, covered by `/gsd-secure-phase` and T-02-07 below.
