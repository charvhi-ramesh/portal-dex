# Phase 1 — UI Design Contract

> Visual and interaction contract for Phase 1: Foundation + Browse. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Sources: `docs/SPEC.md` (sections 4, 5.2, 5.3, 6, 7, 8), `01-CONTEXT.md` decisions D-01 to D-08, `REQUIREMENTS.md`, `ROADMAP.md`. Where this file says "Default", no upstream artifact answered the question and the value is a recommendation the executor must follow.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (stack locked by project constraints; no `components.json`, shadcn not used) |
| Preset | not applicable |
| Component library | none. Hand-built components styled with Tailwind CSS 4 (`@theme` tokens in `app/globals.css`) |
| Icon library | none. Hand-authored inline SVG, 24 x 24 viewBox, 2 px stroke, `currentColor`, `aria-hidden="true"` unless the icon is the only content of a control. No icon package may be added without asking the user |
| Font | Inter via `next/font/google`, weights 400 and 700 only, exposed as `--font-sans`. Replaces the scaffold's Geist fonts |
| Colour scheme | Dark only. Remove the scaffold's light/dark `prefers-color-scheme` palette. Set `color-scheme: dark` on `html` |

Existing scaffold facts (checked 2026-11-11): `app/globals.css` and `app/layout.tsx` are the untouched `create-next-app` output (Geist fonts, white/near-black palette); there is no `src/`, no `components/` folder and no Tailwind config file (Tailwind 4 is configured in CSS). Everything in this contract is greenfield.

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, badge vertical padding |
| sm | 8px | Chip gaps, card body padding on mobile, compact stacks |
| md | 16px | Default gaps, page gutter on mobile, card body padding from 640 px, grid gap on mobile |
| lg | 24px | Page gutter from 640 px, grid gap from 640 px, button horizontal padding, panel padding |
| xl | 32px | Gap between filter bar and count row, footer vertical padding, page gutter from 1024 px |
| 2xl | 48px | Vertical gap between page title block and filter bar, empty/error panel vertical padding |
| 3xl | 64px | Header height, space above the footer |

Exceptions (all intentional):

- **Touch targets:** every interactive control is at least **44 x 44 px** (A11Y-04). Chips, icon buttons (hamburger, search clear) and text buttons are 44 px minimum. Search input and primary/secondary buttons are **48 px** tall (on-scale).
- **`scroll-padding-top` and `scroll-margin-top`: 80px** (header 64 px + 16 px breathing room) so focused or scrolled-to elements are never hidden behind the sticky header (FND-05).
- **Borders and focus ring:** 1 px and 2 px strokes are not spacing and are exempt from the scale.
- **Page container:** `max-width: 1280px`, centred, horizontal padding = gutter (md under 640 px, lg from 640 px, xl from 1024 px).
- **Grid gap:** md (16 px) under 640 px, lg (24 px) from 640 px.

Radius tokens (not spacing): card 20px, panel 24px, input and menu panel 16px, chips, badges, buttons and wordmark pill `9999px` (full).

## Typography

Exactly 4 sizes and 2 weights (400, 700). Inter, `font-feature-settings` default, no letter-spacing changes, no italics.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 400 | 1.5 |
| Heading | 24px | 700 | 1.2 |
| Display | 36px | 700 | 1.2 |

Role assignments:

- **Display (36 px, 700):** the page `h1` ("Browse characters") from 640 px. Under 640 px the `h1` uses Heading (24 px) so it fits 320 px.
- **Heading (24 px, 700):** wordmark "Portal Dex" from 640 px, empty/error state headings (`h2`), fallback-tile initial.
- **Body (16 px, 400):** count line, search input text, footer body, empty/error body copy, chip text is Label (below).
- **Body strong (16 px, 700, line-height 1.2):** card name, button labels, the skip link, wordmark under 640 px, mobile menu links.
- **Label (14 px, 400, line-height 1.5):** chip text, species line on the card, footer disclaimer, "Counting..." placeholder, end-of-list note, desktop nav links (400, 700 when current page).
- **Label strong (14 px, 700):** status badge text, filter group labels, "N collected" counter.
- 14 px is the smallest permitted size. Placeholder text in the search input is Body 16 px in `text-muted`.

Tokens are exactly the spec's section 6 palette plus three UI neutrals added for 3:1 borders and hover. Contrast ratios were computed (WCAG relative luminance) on 2026-11-11 for the FND-01 / X6 gate.

| Accent (10%) | `blue` `#4DA3FF` | See reserved list below |
| Text | `text` `#F2F5FF` | Primary text |
| Text secondary | `text-muted` `#A9B3CC` | Species line, placeholders, filter group labels, footer disclaimer, inactive nav links |
| UI border | `border-ui` `#6B7799` (new) | 1 px borders of inputs and inactive chips, secondary button border, scroll-row edge fade (3:1 required) |
| Divider | `divider` `#252F52` (new, decorative only, no 3:1 requirement) | Header bottom edge, footer top edge |
| Accent hover | `blue-hover` `#7DBAFF` (new) | Hover fill of primary buttons and active chips |
| Status Alive | `teal` `#6FF2D2` | Alive frame and badge fill, focus ring |
| Status Dead | `grey` `#8A93A6` | Dead frame and badge fill |
| Status unknown | `purple` `#A66BFF` | unknown frame and badge fill |
| Favourite | `pink` `#FF7AC8` | Reserved. Not rendered in Phase 1 (star hidden, D-03) |
| Destructive | none | No destructive actions in Phase 1. Errors use neutral `text` and `border-ui` plus an icon and words, never a red |

Accent (blue) reserved for: primary button fill (Retry in the error state, Clear filters in the empty state), active filter chip fill, text links (footer API link, "Clear all"), skip-link fill, current-page underline in the nav. Teal is reserved for the 2 px focus ring and the Alive status. Purple for unknown status only. Blue is never used for card frames, backgrounds or body text.

Verified contrast (WCAG 2.1 AA):

|------|-------|----------|--------|
| `text` on `bg` / `surface` / `surface-raised` | 17.51 / 15.65 / 13.80 | 4.5 | pass |
| `text-muted` on `bg` / `surface` / `surface-raised` | 9.09 / 8.12 / 7.16 | 4.5 | pass |
| `blue` text on `bg` / `surface` | 7.26 / 6.49 | 4.5 | pass |
| `teal` on `bg` / `surface` / `surface-raised` (focus ring, frame) | 13.90 / 12.42 / 10.96 | 3 | pass |
| `grey` on `surface` / `surface-raised` (frame) | 5.52 / 4.87 | 3 | pass |
| `purple` on `surface` / `surface-raised` (frame) | 5.01 / 4.41 | 3 (frame) | pass as border. **Never use `purple` as text on `surface-raised` (4.41 fails 4.5)** |

Rules: text on any accent or status fill is always navy `#0A0F1F`, never white. `purple` and `grey` may be used as text only on `bg` and `surface`, not on `surface-raised`.

## Layout and Structure

### Page shell (root layout)

- `html`: `lang="en"`, `scroll-padding-top: 80px`, `color-scheme: dark`, Inter variable class. `body`: `bg` fill, `text` colour, Body role, `min-height: 100dvh`, flex column so the footer sits at the bottom.
- Landmarks: `<header>` (contains `<nav aria-label="Main">`), `<main id="main-content" tabindex="-1">`, `<footer>`. Exactly one `h1` per page, inside `main`.
- Stacking: star field `-1`, content `0`, menu overlay `40`, sticky header (and menu panel) `50`, skip link `60`.

### Header (FND-02, FND-04)

- `position: sticky; top: 0`, height **64 px**, `bg` fill, 1 px `divider` bottom edge, content container as above, items vertically centred.
- **From 640 px:** wordmark (Heading 24/700, links to `/`, text only, no logo) left; nav links "Browse" and "Collection" (Label, 44 px tall hit area, gap md) after it; "N collected" counter right.
- **Under 640 px:** wordmark (Body strong 16/700) left; counter then hamburger button (44 x 44) right. Nav links live in the menu panel. Width budget at 320 px: wordmark about 85 + counter about 96 + button 44 + gutters 32 + gap 16 = 273 px, so no horizontal scroll.
- Current page link: `aria-current="page"`, `text` colour, weight 700, 2 px `blue` underline at 4 px offset. Other links: `text-muted`, hover `text`.
- **Counter:** pill (`surface` fill, 1 px `border-ui`, Label strong). Phase 1 shows `0 collected` (the favourites store lands in Phase 2). It shows "N collected" and never "N / 0"; it reserves `min-width: 12ch` so the later "N / {total} collected" form does not shift the header. It is not a live region in Phase 1.

### Mobile menu (FND-04)

- Hamburger button: 44 x 44, `aria-expanded`, `aria-controls="mobile-menu"`, accessible name "Open menu" / "Close menu", icon swaps hamburger to ×.
- Panel `#mobile-menu`: `role="dialog"`, `aria-modal="true"`, `aria-label="Main menu"`, drops below the header (top 64 px), full width, `surface` fill, 1 px `divider` bottom edge, bottom radius 16 px, padding lg. Contains Browse and Collection links (Body strong, 48 px tall rows) and nothing else.
- Overlay below the panel: full-screen `bg` at 60% opacity, tap closes the menu.
- Open/close motion: opacity 0 to 1 and `translateY(-8px)` to 0, 200 ms ease-out. Under `prefers-reduced-motion` opacity only, 100 ms.
- Behaviour: closes on Escape, outside tap and route change; traps Tab/Shift+Tab inside panel plus the hamburger button; focus moves to the first link on open and returns to the hamburger on close; the page behind is `inert` while open. Hidden at 640 px and wider (close it if the viewport grows past 640 px).

### Skip link (FND-05)

- First focusable element in the document: "Skip to content", targets `#main-content`.
- Hidden off-screen until focused; on focus it appears fixed at top-left offset md, `blue` fill, navy Body strong text, padding 8 px 16 px, min-height 44 px, radius 16 px, standard focus ring.

### Footer (FND-03)

- `bg` fill, 1 px `divider` top edge, padding xl vertical, 64 px (3xl) margin above.
- Two Label lines: link "Data from The Rick and Morty API" (`blue`, underlined, opens `https://rickandmortyapi.com` in a new tab with `rel="noopener noreferrer"` and a visually hidden " (opens in new tab)") and "Unofficial fan project; not affiliated with the show or its owners." (`text-muted`).
- Stacked and left-aligned under 640 px; one row, space-between, from 640 px.

### Star-field background (FND-07)

- One fixed, `aria-hidden`, `pointer-events: none` layer behind everything (`z-index: -1`).
- Three stacked layers of `radial-gradient` 1 px dots on transparent tiles of 240, 360 and 520 px, dot colour `#C9D4FF` at **no more than 15% opacity** (amended from 35% after Phase 1 research: at 35%, `text-muted` fell to 3.57:1 and blue link text to 2.85:1 where a dot sits behind text; 15% keeps every text pair at 4.5:1 or better, and `scripts/check-contrast.ts` must verify the composited worst case).
- Drift: each layer is oversized by one tile and animated with `transform: translate3d()` by exactly one tile on a **linear, infinite** loop of 90 s, 150 s and 240 s (seamless). Only `transform` animates. `will-change: transform` on the three layers only.
- Under `prefers-reduced-motion: reduce`: `animation: none` (static dots).

### Browse page (`/browse`)

Top to bottom inside `main` (container padding top 32 px mobile, 48 px from 640 px):

1. `h1` "Browse characters" (Display from 640 px, Heading under; `tabindex="-1"` so client navigation can focus it, `outline: none` on programmatic focus). `document.title` is "Browse · Portal Dex".
2. 48 px gap (2xl), then the filter bar (static, not sticky, D-06):
   - Search field, then three chip groups (Status, Gender, Species), stacked with 16 px between groups and 24 px between search and the first group.
3. 32 px gap (xl), then the **results toolbar row** (see below). This row is the scroll target for BRW-10 (`scroll-margin-top: 80px`).
4. 16 px gap, then the card grid, then the Load more / end-of-list / inline error area, then the footer.

### Search field (BRW-02)

- `<input type="search">` with a visually hidden `<label>` "Search characters by name"; placeholder "Search by name". Height 48 px, `surface` fill, 1 px `border-ui`, radius 16 px, left padding 48 px for a 24 px search icon (`text-muted`), right padding 48 px for the clear button. Hover: `surface-raised` fill. Focus: standard focus ring (below) in addition to the border. Full width under 640 px, `max-width: 480px` from 640 px.
- Clear button: 44 x 44 icon button (×), accessible name "Clear search", rendered only when the input has a value, positioned inside the right edge. Native browser search-cancel button is hidden (`appearance: none`) to avoid a double ×.
- `maxLength={60}`, `autocomplete="off"`, `spellcheck="false"`, `enterkeyhint="search"`.
- Debounce 300 ms. Escape clears the value, cancels any pending debounce and keeps focus in the input. × click clears and returns focus to the input.

### Filter chips (BRW-03, BRW-04; D-07)

- Each group: wrapper `role="group"` with `aria-labelledby` pointing at a visible group label (Label strong, `text-muted`: "Status", "Gender", "Species"), label above the row, 8 px gap.
- Chips are `<button type="button" aria-pressed="true|false">`, min-height 44 px, min-width 44 px, horizontal padding 16 px, pill, Label text.
  - Inactive: `surface` fill, 1 px `border-ui`, `text`. Hover: `surface-raised` fill.
  - Active: `blue` fill, navy text, no border change, leading 16 px check icon. Hover: `blue-hover` fill.
  - Colour changes are instant (no colour transitions). Press feedback: `transform: scale(0.97)` 150 ms, reset on release.
- Values (exact, in this order): Status: Alive, Dead, unknown. Gender: Female, Male, Genderless, unknown. Species: Human, Alien, Humanoid, Mythological Creature, Robot, Animal. Chip labels render the API value except "unknown", which renders "Unknown" (the URL value stays lower-case `unknown`).
- One value per group; pressing the active chip deselects it. Focus stays on the chip after activation (never remount chips).
- **Under 640 px:** each group's row is a single horizontally scrolling line (`flex-wrap: nowrap; overflow-x: auto`, hidden scrollbar, `scroll-padding-inline: 16px`), edges bleed to the viewport edge, and the trailing edge shows a 24 px fade mask so a clipped chip hints at more. The row is keyboard-reachable because its chips are focusable (focus scrolls the chip into view); the labelled group provides the region name (A11Y-05). **From 640 px:** chips wrap (`flex-wrap: wrap`, 8 px gap both axes).

### Results toolbar row (Claude's discretion, resolved)

- One row, `min-height: 44px` (reserved so nothing shifts), `display: flex; justify-content: space-between; align-items: center`.
- **Left: count line** (Body, `text`): "N characters" with thousands separators via `Intl.NumberFormat("en")`. Singular "1 character". Zero: "0 characters". While the derived Human total or the first page is loading, the line shows "Counting..." in `text-muted` inside a slot with `min-width: 16ch`, so the final number does not shift the row (D-08).
- **Right: "Clear all"** text button (Body strong, `blue` text, 44 px tall, padding 0 8 px, underline on hover). It is **only rendered when search or any chip is active**, so there is no dead tab stop, and the row's reserved 44 px height means it appearing or disappearing never moves content.
- The count line is visual only. Announcements go through one separate live region (below).

### Live region (BRW-07, BRW-08; D-08)

- One always-mounted, visually hidden `<div aria-live="polite" aria-atomic="true">` on the Browse page. Visible count text is **not** also live (avoids double announcements).
- It receives text only when the value is final: the settled total after a search/filter change or first load ("826 characters" style), then "{n} more characters loaded" after each next page where `n` is the number of cards actually added (not a fixed 20; exact-species filtering can change the page yield). It is never written during "Counting..." and never written with a raw `info.count` for the Human chip. For zero results it receives "No characters in this dimension". Message updates are debounced to settle after the last data change so rapid chip changes announce once.

### Card grid (BRW-01)

- `<ul>` with `list-style: none`, CSS grid, items `<li>` (one card each).
- Columns: **2** under 640 px, **3** from 640 to 1023 px, **4** from 1024 to 1279 px, **5** from 1280 px. Gap 16 px under 640 px, 24 px from 640 px. Cards stretch to equal height per row.
- Whole grid has `aria-busy="true"` while its first page is loading.

### Character card front (CARD-01, CARD-08; D-01 to D-05)

Fixed structure (final markup from Phase 1 per D-01). Inside `<li>`: a card wrapper `<article>` with `tabindex="-1"` (programmatic focus target only, never a tab stop), `data-status="alive|dead|unknown"`, containing in this DOM order:

1. **Flip button** (`<button type="button" disabled aria-hidden="true">`): a direct sibling of the star slot and the link slot, never their ancestor; absolutely positioned to cover the card face; fully transparent, `cursor: default`, no hover or focus styling (D-02). It is not focusable in Phase 1 and must not look disabled. Phase 2 removes `disabled` and `aria-hidden` and adds the accessible name and `aria-pressed`.
2. **Front face:** avatar then body (below).
3. **Star slot:** an empty, reserved 44 x 44 px element at the top-right of the avatar (D-03). Nothing rendered, nothing focusable.
4. **Link slot:** empty placeholder for Phase 2's "View details" (nothing rendered).
5. **Back face (stub):** `inert`, `transform: rotateY(180deg)`, `backface-visibility: hidden`, empty. It exists only so Phase 2 adds behaviour, not markup.

Visual spec of the front:

- Frame: 2 px solid border in the status colour (D-04), radius 20 px, `surface` fill, overflow hidden. Alive `#6FF2D2`, Dead `#8A93A6`, unknown `#A66BFF`. **Static in Phase 1**: no glow, pulse, shimmer or grayscale on the avatar, and no hover effect on the card (it is not interactive until Phase 2).
- **Avatar:** 1:1, full-bleed across the top inside the frame (top corners follow the card radius), rendered with `next/image` (`alt` = character name, `sizes="(min-width: 1280px) 20vw, (min-width: 1024px) 25vw, (min-width: 640px) 33vw, 50vw"`, first row eager and the rest lazy). While loading: solid `surface-raised` block (no shimmer), image fades in with `opacity` 0 to 1, 200 ms. On error: fallback tile, same 1:1 box, `surface-raised` fill, the name's first letter in Heading 24/700 `text-muted` centred, `role="img"` with `aria-label` = character name.
- **Body** (padding sm 8 px under 640 px, md 16 px from 640 px; vertical gap 8 px):
  1. Name: `h2`, Body strong (16/700, line-height 1.2), `text`, clamped to 2 lines (`line-clamp-2`), box height reserved for 2 lines (`min-height: 2.4em`), full name in `title`.
  2. Status badge: pill, Label strong, text label always shown ("Alive", "Dead", "Unknown"), padding 4 px 8 px, fill = status colour, navy text. Status is never colour only.
  3. Species: Label, `text-muted`, single line with ellipsis, full value in `title`. Empty or missing species renders "Unknown species".
- **Skeleton card:** identical outer box (frame in `border-ui`, 2 px), `surface-raised` avatar block, three `surface-raised` bars matching name (2 lines), badge and species widths. Same heights as the real card so scroll restoration and skeleton to content swap never shift layout. Skeleton animation: `opacity` 1 to 0.5 to 1 over 1.6 s ease-in-out infinite; `prefers-reduced-motion`: static at opacity 0.75. Skeletons are `aria-hidden`.

### Skeleton counts

- Initial load or filter change: render `2 x columns` skeleton cards (4 / 6 / 8 / 10 for the 2 / 3 / 4 / 5 column layouts; render 10 and hide the extras with breakpoint classes).
- Next-page load: one row of skeletons appended (2 / 3 / 4 / 5), same technique.

### Load more, end of list and inline error (BRW-08, BRW-09)

- **Load more:** secondary button (see Buttons), centred, 24 px below the grid, shown whenever another page exists (the keyboard fallback to infinite scroll). While fetching it stays mounted with label "Loading more..." and `aria-disabled="true"` (never `disabled`, so focus is not lost).
- **Infinite scroll:** an `IntersectionObserver` sentinel with `rootMargin: 0px 0px 400px 0px` sits after the grid. Auto-loading is suspended while a next-page error is showing, until the user presses Retry.
- **Focus after Load more activation:** the first newly added card (`<article tabindex="-1">`) receives programmatic focus with the standard focus ring, and the live region announces "{n} more characters loaded" (X4). If there is no next page afterwards, focus goes to the end-of-list note (`tabindex="-1"`) because the button unmounts.
- **End of list:** when the last page is reached (a 404 on page > 1, DATA-03), the Load more button is removed and a centred Label `text-muted` note reads "You've reached the end of the dimension." No error panel, no empty state.
- **Inline next-page error:** below the grid (existing cards stay): `role="alert"`, centred row with a 24 px alert icon, "Couldn't load more characters." and a secondary "Retry" button.

### Empty and error panels (BRW-09)

- Panel: centred in the grid area, `max-width: 480px`, `surface` fill, 1 px `border-ui`, radius 24 px, padding 48 px vertical / 24 px horizontal, stacked and centred: 64 px decorative icon (`aria-hidden`, `text-muted`), Heading `h2`, Body copy, primary button, 16 px gaps.
- Empty and error never render at the same time. A 404 on page 1 of a filtered query is always the empty state (DATA-03); only network, 5xx and abort-unrelated failures are the error state. Error panel has `role="alert"`.

## Focus ring (A11Y-01)

Every focusable control and programmatic-focus target uses one shared style: `outline: 2px solid #6FF2D2; outline-offset: 2px`, applied on `:focus-visible`. Where a control sits on an accent fill (primary button, active chip, skip link) the offset keeps the ring on the `bg`/`surface` behind it, so it stays at 3:1 or better. The card-frame-aware ring (navy inner, teal outer) is verified in Phase 2 (CARD-07, D-05).
